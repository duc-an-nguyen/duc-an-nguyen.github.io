Metrics for Object Detection

Understanding why detection loss is not enough and how IoU, TP, FP, FN, precision, recall, F1 score, AP, and mAP evaluate real detection performance.

Object Detection Evaluation Metrics October 2026

Many object detection models have been developed, and most of them are trained the same way: by minimizing a loss function that measures the gap between the model’s predictions and the ground truth. But has anyone ever stopped to ask:

If the loss function already tells us how far the predictions are from the ground truth, why don't we simply evaluate a model by its loss on the test set? Why do we need other evaluation metrics at all?

This article answers that question, then walks through why each metric is needed and the concept behind it.

Why Is Loss Not Enough to Evaluate Object Detection?

Training objectives and predictions

Suppose we are training YOLO to detect drones in thermal images. We start with two pieces of information:

  • Ground truth: the correct annotations (boxes and class labels) provided in our dataset.
  • Predictions: the boxes, class labels, and confidence scores produced by our neural network.

Our objective is to make the predictions as close to the ground truth as possible (see Figure 1). The loss function measures how far the predictions are from the ground truth, and training minimizes it. In object detection, this loss typically combines several components, such as bounding-box localization errors, classification errors, and, depending on the architecture, objectness errors.

Why not compare loss alone?

So why not simply use the loss to evaluate the model?

We can evaluate and compare models using their loss values on unseen data, as long as they are evaluated on the same dataset using the same loss function and calculation settings. In regression, standard metrics such as MSE, MAE, and RMSE are commonly used to measure and compare prediction errors.

But in object detection, the loss varies across models and even across versions. For example, YOLOv5 includes an objectness loss term that YOLOv8 does not, while Faster R-CNN and DETR use different loss formulations. Even when the loss definitions are identical, the loss does not answer the questions people care about: how many objects were found, how many detections were false alarms, and how many objects were missed.

Comparing two detection models

For example, consider two models, A and B, evaluated on the same validation dataset using the same confidence and IoU thresholds. Suppose the results are:

Evaluation result Model A Model B
Total ground-truth drones 10 10
Correctly detected drones 9 7
False alarms 6 1
Missed drones 1 3

Model A detects more drones but produces more false alarms, while Model B detects fewer drones but produces fewer false alarms. So, which model is better?

It depends on the application. If detecting as many drones as possible is the priority, Model A may be preferable. However, if minimizing false alarms is more important, Model B may be the better choice.

This example shows why we need evaluation metrics to measure different aspects of detection performance and understand the trade-offs between them.

But before diving into concepts such as True Positive (TP), False Positive (FP), False Negative (FN), precision, and recall, we first need to understand how to determine whether a detection is correct or incorrect. After all, we need to count correct detections, false alarms, and missed objects to calculate these metrics. This is where IoU comes in, helping us determine whether objects are correctly localized within images.

Note

IoU can also be used during training as part of a bounding-box loss. However, here we focus on its role in evaluating detections.

Intersection over Union (IoU)

What makes a detection correct?

A correct class is not enough to call a detection correct. A detection says two things: what the object is (the class) and where it is (the box). For example, a box covering the whole image and labeled “drone” has the right class, but it does not locate the drone. So the predicted box must also overlap the ground-truth box well enough.

To count TP, FP, and FN, each prediction therefore has to pass three checks:

  1. Class: whether the predicted label is the same as the real object’s label
  2. Confidence: the model’s score for that label is above the chosen threshold, so the prediction is kept
  3. Location: its box overlaps the ground-truth box well enough

The first two are easy to check: compare a score with a threshold, and check that two labels are the same. The third has no ready-made number, so we need one that measures how well a predicted box fits the ground-truth box. That number is IoU (see Figure 2), which measures how closely a predicted bounding box overlaps the real bounding box.

How IoU measures overlap

IoU = Intersection AreaUnion Area

A higher IoU value means the predicted box fits the ground-truth box more closely. A lower value means the boxes overlap less, because the prediction is shifted, too small, or too large. The maximum is 1 for identical boxes, and 0 means no overlap. Like the confidence score, it is compared with a threshold t (commonly 0.5): the location check is passed when IoU ≥ t.

Once every prediction has been checked for class, confidence, and IoU, we can count for TP, FP, FN. These counts feed the next evaluation stages (Precision, Recall, F1, AP, mAP), so IoU is only a middle step: Its main role is to measure the overlap between predicted and ground-truth boxes, helping determine whether a prediction is a TP, FP, or FN, and it is not a score for the whole model.

Now let’s dive into the concept of TP, FP, and FN

True Positive, False Positive, and False Negative

Understanding detection outcomes

At first, we might think that counting the number of correct predictions out of the total is enough to evaluate a model. However, looking at only one side is not sufficient. What if the model incorrectly identifies an object as a true detection? This could lead to many false alarms, even if the model correctly detects most real objects. Therefore, we need to consider both correct and incorrect predictions to properly evaluate the model. This is where we come to the concepts of TP, FP, FN, and TN (see Figure 3)

The rule is:

  • Positive / Negative: Did the model detect the object?
  • True / False: Was it right?
Concept Explanation Example
TP (True Positive) The model detects an object correctly A drone exists, and the model detects it
FP (False Positive) The model detects something incorrectly No drone exists there, but the model predicts a drone
FN (False Negative) The model misses a real object A drone exists, but the model doesn't detect it.
TN (True Negative) The model correctly identifies that an object is absent No drone exists, and the model correctly predicts no drone.
Notice

The concept of TN is normally not used in object detection, while it’s common for classification, segmentation, and other computer vision tasks

From counts to evaluation metrics

TP, FP, and FN represent the numbers of correct detections, false alarms, and missed objects. However, these raw counts alone can be difficult to compare across datasets of different sizes. To better understand and compare model performance, we use Precision and Recall to express these results as percentages.

Precision, Recall, and F1 Score

Precision versus recall

The table below provides a comparison of precision and recall:

Precision Recall
Tells us how many predictions are correct out of all predictions made by the model. Or, in a simple way: Of everything the model detected, how much was correct? Measures how many real objects the model correctly detects out of all real objects in the ground-truth dataset. Or, in simple terms: Of everything that actually exists, how much did the model detect?
Precision = TP / (TP + FP) Recall = TP / (TP + FN)
TP: Number of correctly detected objects.
TP + FP: Total number of objects predicted by the model.		 TP: Number of correctly detected objects.
TP + FN: Total number of real objects in the ground truth.

Precision and recall measure different aspects of detection performance: precision reflects how well a model avoids false detections, while recall reflects how well it avoids missing real objects.

Choosing a confidence threshold

Increasing the confidence threshold means the model accepts only its most confident predictions, generally leading to higher precision but lower recall (more missed objects or false negatives). Conversely, decreasing the confidence threshold means the model accepts more predictions, leading to higher recall but lower precision (more false alarms or false positives) (see Figure 4).

Therefore, we need the F1-score to combine both metrics into a single value that measures how well the model balances Precision and Recall.

Balancing both with F1

F1 = 2 × Precision × RecallPrecision + Recall

The F1 score is useful when we want to balance minimizing false detections and avoiding missed detections. To achieve it, we need to choose an appropriate confidence threshold for deployment, for example, by examining the F1–confidence curve.

Average Precision (AP)

Evaluating multiple confidence thresholds

Although the F1 score balances precision and recall, all three metrics are calculated at a single confidence threshold (e.g., 0.25). We need a metric that can evaluate model performance across different confidence thresholds, and that’s why we need AP.

AP summarizes the Precision–Recall behavior across different confidence thresholds, giving us a broader measure of detection performance. For example, we have a table of results for precision and recall over different confidence scores

Confidence threshold TP FP FN Precision Recall
0.90 2 0 8 100% 20%
0.70 5 1 5 83.3% 50%
0.50 8 2 2 80% 80%
0.30 9 6 1 60% 90%

The precision–recall curve

Looking at the table, we see that:

  • At threshold 0.90, Precision is high, but YOLO misses many drones.
  • At threshold 0.30, YOLO finds almost all drones, but accepts more false detections.
  • AP summarizes performance across the full Precision–Recall curve, rather than selecting only one of these rows.

By plotting precision on the y-axis and recall on the x-axis, we obtain a precision–recall curve.

AP represents the area under the interpolated precision–recall curve, also called the precision envelope

AP = ∫01 Pinterp(r) dr
  • AP: Average Precision.
  • P_interp(r): Interpolated precision at recall level r.
  • r: Recall, ranging from 0 to 1.

Interpreting the AP score

High AP indicates that the model generally maintains high precision as recall increases, meaning it detects many real objects while keeping false detections relatively low.

Low AP indicates that the model struggles to maintain high precision across recall levels, meaning it may miss many objects, produce many false detections, or both.

Mean Average Precision (mAP)

Averaging AP across object classes

While AP measures detection performance for a single class at a specific IoU threshold (across different confidence thresholds), object detection models often detect multiple classes. This is why we need mAP, which measures overall detection performance by averaging the AP scores across all classes.

mAP@50 and mAP@50–95

Since AP is calculated at a specific IoU threshold, mAP can also be evaluated at different IoU thresholds. Two commonly used metrics are mAP@50 and mAP@50-95.

  • mAP@50: Uses an IoU threshold of 0.50. A predicted box is considered a correct detection if it has the correct class and matches an unmatched ground-truth box with IoU ≥ 0.50
  • mAP@50-95: Averages mAP across 10 IoU thresholds, from 0.50 to 0.95 in steps of 0.05. It is stricter than mAP@50 because it rewards precisely placed boxes, so its value is usually lower than mAP@50
